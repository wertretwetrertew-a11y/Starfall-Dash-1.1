# Starfall Dash — текущая архитектура и безопасный переход

## Текущая рабочая схема

Игра пока остаётся на текущей структуре. Основные браузерные скрипты подключаются из index.html в определённом порядке:

1. js/balance-config.js
2. js/core-data.js
3. js/meta-ui.js
4. js/gameplay.js
5. js/roguelike-v3.js
6. js/rogue-planets.js
7. js/menu-motion.js

Это порядок загрузки, поэтому первые рефакторинги не должны нарушать его без явной замены зависимостей.

## Главные текущие зоны ответственности

- core-data.js — общие DOM-ссылки, игровые данные, сохранения, классы и связанные базовые системы.
- meta-ui.js — профили, магазин, кейсы, ядро, ежедневный бонус, HUD и мета-интерфейс.
- gameplay.js — основной игровой цикл, игрок, враги, столкновения, обновление состояния, отрисовка и значительная часть игровых механик.
- roguelike-v3.js — Roguelike-слой, классы/способности и run-only прогрессия.
- rogue-planets.js — планеты, этапы и специальные Roguelike-правила.
- balance-config.js — сгенерированные runtime-данные баланса; источник — config/roguelike-balance.json.
- tools/ — developer-only инструменты. Особенно важен Balance Editor: он локально редактирует баланс и может создавать commit/push.

## Безопасный порядок миграции

1. Зафиксировать рабочую точку и отдельную ветку.
2. Добавить только инфраструктурные файлы, не меняющие игровой runtime.
3. Зафиксировать карту зависимостей.
4. Отделить данные от логики без изменения поведения.
5. Отделить Survival/Roguelike.
6. Отделить UI-модули.
7. Только затем разделять gameplay/core/rendering.
8. После каждого этапа проверять запуск игры и критические сценарии.

## Что не менять в рамках архитектурной миграции

- игровой баланс;
- визуальный дизайн;
- позиции UI;
- правила Survival;
- существующие способности;
- сохранения;
- Bot Lab;
- launcher.

Любое такое изменение должно быть отдельной задачей/commit.

## Правило Bot Lab

Balance Editor должен оставаться developer-only инструментом. Перед его переносом необходимо убрать жёсткую привязку к git push origin main, чтобы архитектурная рабочая ветка не могла случайно отправить изменения напрямую в main.
